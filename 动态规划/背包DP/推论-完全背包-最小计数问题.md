## 名称与地位
零钱兑换，完全背包入门题

## 用途
最少找零张数、邮票问题、最少步数爬楼梯（步长集合固定）等

## 核心原理
对比模板，只改三处：
1. **聚合函数**：`max` → `min`（我们要"最少枚数"，不是"最大价值"）
2. **初始化**：`f[0] = 0`，其余全部 `INF`（表示"暂未凑出"）
3. **物品语义**：硬币面额既是重量又是价值，`f[j]` 直接表示**凑出 j 元最少需要几枚**

```cpp
f[0]=0;
for(int i = 1; i <= n; i++) {
	for(int j = a[i]; j <= S; j++) {
		f[j] = min(f[j], f[j - a[i]] + 1);
	}
}
cout << ( f[S] == INF ? -1 : f[S] );
```

|变量|含义|
|---|---|
|`INF`|"Infinity" 的缩写，表示**无穷大**（即"不可达"）。取 `0x3f3f3f3f` 是有讲究的：它约等于 10⁹，足够大，且满足 `0x3f3f3f3f + 0x3f3f3f3f` 不溢出 int（两个 0x3f 相加仍是合法的），方便直接做加法。`0x3f3f3f3f` 里每字节都是 0x3f，还有一个好处是 `memset(arr, 0x3f, sizeof arr)` 能直接整体初始化成 INF|
|`n`|硬币的**种类数**|
|`a[i]`|第 i 种硬币的**面值**（数组 a 是 amounts）|
|`S`|目标**总金额**（Sum）|
|`f[j]`|**状态数组**：凑出金额 j 所需的**最少硬币数**。`f` 常取 function 的首字母|
|`f[0] = 0`|凑出 0 元需要 0 枚硬币，这是边界条件（起点）|
|`i`|外层循环变量，正在考虑**第 i 种硬币**|
|`j`|内层循环变量，正在计算**凑出 j 元**的最优解|

**为什么还是正序？** `f[j - a[i]]` 可能已经用过了第 i 种硬币，于是 `+1` 相当于"在它基础上再贴一枚同种硬币"——这正是"无限件"的语义。负序的话 `f[j-a[i]]` 保证没用过 i，那就退化成 01 背包了。

**为什么要 INF 初始化？** min 聚合的"空状态"必须是"无穷大"而不是 0，否则"不选"会被当成"花 0 枚凑出任意金额"，全表都会被刷成 0。这是和 max 版最大的思维差异点，也是初学者最常见的翻车处。

**判无解**：凑不出来时 `f[S]` 从未被更新，仍是 INF，输出 -1 即可。

# 例题
## 入门：洛谷 B3635 硬币问题（普及−）
传送门：[https://www.luogu.com.cn/problem/B3635](https://www.luogu.com.cn/problem/B3635) [[题解-P3635 硬币问题]]

> 今有面值为 1、5、11 元的硬币各无限枚。想要凑出 n 元，问需要的最少硬币数量。
> 输入：仅一行，一个正整数 n。输出：最少硬币个数。
> 样例：输入 `15` → 输出 `3`（5+5+5）；输入 `12` → 输出 `2`（11+1）。

这就是纯粹的"完全背包求 min 计数"，把我上次给的板子原样套上去就能 AC——硬币既是重量又是"1 的价值"，连输入数组都省了。

**这题有个著名的坑**：1、5、11 这组面值看起来 greedy 很香（每次拿不超过剩余金额的最大面值），但对 n=15，贪心会拿 11+1+1+1+1 共 5 枚，正解却是 5+5+5 只有 3 枚。所以别被"硬币问题 = 贪心"的直觉骗了，这题就是拿来区分贪心思维和背包思维的。

## 进阶：洛谷 P2851 [USACO06DEC] 最少的硬币 The Fewest Coins（提高）

传送门：[https://www.luogu.com.cn/problem/P2851](https://www.luogu.com.cn/problem/P2851)

这题是上一题的"实战加强版"：FJ 买价值 T 的东西，他自己每种硬币数量有限（**多重背包**，还要二进制优化），店主硬币无限（**完全背包**，正序 min），求"付出的硬币数 + 找零的硬币数"总和最小。答案是 `min(f[i] + g[i-T])`，枚举付款金额 i 从 T 到 T + Vmax²（上界用抽屉原理证明，这本身就是个考点）。

如果你刚学完完全背包，建议先把 B3635 裸模板写顺，P2851 作为"完全背包 + 多重背包"的综合练习留到后面。写完了或者卡在边界判断上，随时把代码贴过来我帮你看。
